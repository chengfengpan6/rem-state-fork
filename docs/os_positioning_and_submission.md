# Organizational question and research-artifact scope

Updated 25 October 2026. This document explains the scientific positioning of the prototype. It does not represent a submitted manuscript or editorial endorsement.

## What the instrument is for

When factual records remain available, does an inherited shared interpretation of who is reliable in which context change subsequent evidence use and collective judgment? Organizations preserve observations and interpretations, but these ordinarily evolve together with interaction and subsequent decisions. REM separates external state objects so that a specified representation can be changed at a common checkpoint while future external evidence remains matched.

The instrument concerns a public reliability representation, not a complete model of human organizational memory. Signals are disclosed mechanically so that the core question concerns interpretation after the factual signals are shared. This deliberately excludes hidden-profile discovery, strategic concealment and endogenous disclosure. Keeping records available also means that removing the external map at the fork does not remove experience, eliminate prior beliefs, or prevent reconstruction.

The primary planned scientific contrast is P−E: replace an evidence-derived map with a deliberately altered version while matching its format and provenance. It examines content replacement in an inherited common object. H−E connects the instrument to an endogenously generated summary. History diagnostics, actual H error, sharedness, reported estimates and subsequent behavior are separate objects; none should be used as an automatic substitute for another. The implementation and run manifests determine which contrasts have actually been executed.

## What would count as a contribution

The intended contribution is an inspectable experimental capability: separate factual experience from an inherited interpretation, trace the treatment into actual requests, observe reconstruction and judgment, and identify when a measurement does not support the proposed inference. A reproducible failure or a carefully diagnosed null can be useful. Merely producing more model responses or showing that wording changes an answer is insufficient.

The organizational basis includes learning from organizational codes and distinct levels of belief ([March, 1991](https://doi.org/10.1287/orsc.2.1.71)); distinctions among accuracy, sharedness and participation in transactive memory ([Brandon and Hollingshead, 2004](https://doi.org/10.1287/orsc.1040.0069)); and attention to the object and carrier of organizational forgetting ([de Holan and Phillips, 2004](https://doi.org/10.1287/mnsc.1040.0273)). These works constrain the interpretation. They do not supply the harness's numeric reliability matrix, map permutation, update interval or sample size.

Technical novelty must be assessed against existing memory interventions, collective misremembering, counterfactual replay and memory governance. Relevant neighbors include [Xiong et al., ACL 2026](https://doi.org/10.18653/v1/2026.acl-long.27), [Xu et al., 2026](https://doi.org/10.48550/arXiv.2602.00428), [AgenTracer](https://doi.org/10.48550/arXiv.2509.03312), [MINJA](https://doi.org/10.52202/085713-1554), and [Governed Shared Memory](https://doi.org/10.48550/arXiv.2606.24535). The last is a preprint; the arXiv links identify the versions used for comparison, not invented conference DOIs. REM does not claim to introduce memory intervention or replay in general.

## Evidence and interpretation

| Evidence | What it can establish | What it cannot establish alone |
|---|---|---|
| Offline tests and semantic mutations | Specified code properties and rejection of tested errors | Real-model protocol fidelity or organizational validity |
| Completed real-model run | The recorded configuration executed with the reported responses and failures | Adequate power, independent histories, human external validity or a mechanism |
| Exact replay | Recorded outputs reproduce checked downstream objects | A fresh provider call will return the same output |
| Matched P−E comparison | Consequences of the specified map-content intervention, conditional on delivery and design | The effect of naturally generated H, or complete organizational memory |
| H−E comparison | Differences involving endogenous summaries | Pure content effects if provenance or presentation also differ |
| Terminal map update | An update operation was performed | Correction in subsequent decisions without later forecasts |

Independent units are histories or fork families. Actors, rounds, map cells and batched probes are repeated observations within them. A/A branches must obtain separate responses rather than duplicate one trace. Provider randomness, context and model drift require explicit limits even when the harness is deterministic.

## Fit with the Organization Science call

The [official special-issue call](https://pubsonline.informs.org/pb-assets/filesorsc/CFP_AI-Enabled%20Frontiers%20in%20Organizational%20Science-1785685920943.pdf), checked 25 October 2026, welcomes synthetic social systems, reusable research infrastructure and boundary-setting work. A Stage-1 package comprises a roughly 3–5 page, 1,500–2,000 word proposal plus references, a technical appendix and a Git repository or equivalent prototype. The proposal describes completed work, intended development, risks, and the resulting change to science. A repository alone does not satisfy the package.

Stage 1 closes 1 November 2026; no exact deadline timezone was established. The call does not specify a minimum number of model responses or a mandatory model. Final artifacts must be publicly accessible through GitHub or an equivalent research object; Stage 1 does not prescribe GitHub as the sole host. The [general submission instructions](https://pubsonline.informs.org/page/orsc/submission-guidelines) and [transparency policy](https://pubsonline.informs.org/page/orsc/data-and-methods-transparency) govern anonymous review, AI disclosure, research chronology, related work and author attestations.

## Reuse and public-release boundaries

Public release should include original shareable source, tests, task configurations, synthetic evidence, and instructions tied to the actual version. Preserve unmodified original research traces and label transformed review copies separately. Exclude credentials, private correspondence, recordings, unrelated projects and third-party manuscript attachments. A software license applies only to its stated scope; it does not grant rights over proprietary models or third-party material.

An anonymous local export, a publicly accessible development repository and an externally verified review link are different artifacts. None should be claimed from the existence of another. Code validation and substantive research validity are likewise distinct: the goal is to make both inspectable, including the limitations that remain.
